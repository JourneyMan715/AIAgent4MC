### 3.2 先轮换，再谈清理

**顺序不能反**：

1. 去模型后台把 `旧 key` 与 `当时 key` 两个 key **都作废**，重发新的；
2. 改皮肤站密码；

4. 最后清理历史（否则清了也没意义，key 已经泄露过）。

### 3.3 历史清理的两种方案

#### 方案 A（推荐）：发布「干净的新仓库」

不携带旧历史，最简单、最安全：

```bat
:: 1) 复制一份干净工作树（不要 .git / .env / state / logs / node_modules / venv / .bat）
:: 2) 在新目录初始化
git init
git add .
git commit -m "initial public release"
git remote add origin <你的新仓库>
git push -u origin main
```

#### 方案 B：保留历史，重写提交

需要 `git filter-repo`（或 BFG），并通知所有协作者重新克隆：

```bat
pip install git-filter-repo

:: replacements.txt 里写「完整旧值==>REDACTED」，从 .env / git show 里取完整值，
:: 写完立刻删除这个文件，别提交
git filter-repo --replace-text replacements.txt

:: 顺手改作者邮箱（可选）
git filter-repo --mail-map mailmap.txt

git remote add origin <新远端>
git push --force --all
```

> 若仓库已经公开过：**无论是否重写历史，都必须先轮换 key**。历史可能已被缓存/fork。
