# 一、活动详情

## 1. 活动定位与目标

随着大语言模型与 Agent 技术不断发展，如何使智能体在复杂、开放、动态的环境中自主决策、长期存续并完成目标任务，已成为重要研究方向。Minecraft 拥有开放世界、生存压力、经济与任务系统，非常适合作为 AI Agent 的综合性测试平台。

本次活动目标：

- 推动校内同学了解并实践 AI Agent、工具调用、任务规划、记忆机制、模型微调等相关技术；
- 探究大模型在 Minecraft 生存场景下的自主决策能力；
- 推动南京大学学生 Minecraft 协会（NMO）与南京大学学生人工智能协会（AIA）两个社团跨社团协作；
- 产出可复用的 Agent 评测接口、评测流程以及社区活动组织经验。

本赛事将 Minecraft 生存世界作为开放式试验环境，鼓励参赛选手开发具备环境感知、任务规划、自主行动能力的智能 Agent。技术方案不限大语言模型，强化学习、专用决策模型等其他技术路线均可参赛。赛事看重技术创意、游戏内自主行为、互动性与观赏性，不将单一任务完成率、固定模型基准作为唯一评判标准。

分工安排：NMO 负责提供独立生存世界、统一 Agent 接口、游戏端技术保障和游戏内容评审；AIA 承担模型赛道评审、统一模型 API、Token 资源、算力协调以及 AI 相关技术支持。

## 2. 赛事赛道与入围机制

本赛事设立 Harness 赛道、Model 赛道。竞赛为组队赛制，每队参赛人数 1 至 4 名。队伍队长必须是南京大学在校学生，队员身份不限，可为外校学生。

### 2.1 Harness 赛道

- **统一模型；接入 AIA 提供的统一代理 API；不得改用其他大模型或通过外部服务绕开额度约束。**
- 参赛内容：自行设计 Harness，包括规划调度、记忆、工具调用、状态维护、行为策略、多 Agent 协作等；统一通过 NMO 接口操控 Minecraft Agent。
- 11 月 22 日开展 8 小时初赛；参考世界内表现、创造力、稳定性及可观赏性等综合评议，选出 8 支队伍进入决赛，具体评议细则与 NMO 协商发布。
- 比赛内允许修改提示词、调试框架和重启程序；禁止参赛人员直接代替 Agent 执行游戏行为。

### 2.2 Model 赛道

（与 Harness 赛道无关，略。要点：11/21 材料初评；11/23 起一队一张 W7900D；决赛只能用分配的单卡推理。）

## 3. 比赛环境与互动原则

- 每场实战比赛使用 NMO 提供的一套独立 Minecraft 生存世界。该场全部参赛 Agent 共享同一世界，同时存在、自由行动；不分队伍创建独立副本。
- 初赛和决赛分别创建新世界，避免前阶段资源积累带来优势；具体游戏版本、地图、出生配置、任务机制和接口规则以 NMO 单独发布的文件为准。
- MC Advancement 提供探索与发展的参考主线，但不强制遵循。队伍可以自由选择建筑、农业、红石工程、地下探索、屠龙、协作乃至自创目标。
- 允许正常资源竞争和自愿协作；禁止利用漏洞、观众操控、人工代打、恶意攻击比赛基础设施或持续性阻止其他 Agent 正常比赛。世界内 PvP、破坏和资源争夺的边界由 NMO 提前公布并执裁。
- 人类观众可按 NMO 安排以观察者身份进入世界观赛，不得产生物品、修改世界、发送可影响 Agent 的指令或以任何其他形式干预比赛。全程组织直播与精彩片段记录。
- NMO 配置服务器监控与世界快照（建议每 15—30 分钟）；若出现崩服、严重插件故障或大范围恶意破坏，由裁判组决定暂停、修复、回滚或调整剩余时间。

# 二、初赛规则（Minecraft Agent 挑战赛）

## 1. 活动目标

参赛者需要设计一个能够通过赛事 API 自主游玩 Minecraft 的智能 Agent。在规定时间内，Agent 应自行观察环境、制定计划并执行操作，**尽可能完成更多原版 advancement，获得更高总分**。

## 2. 比赛时间

每场比赛时长为 **8 小时**，自裁判系统宣布比赛开始时计时。

比赛结束后，所有新产生的操作和 advancement 均不再计入成绩。因参赛程序、网络连接或模型服务造成的中断仍计入比赛时间，不另行补时；若赛事服务器发生统一故障，则由主办方决定是否暂停、补时或重赛。

## 3. 初始状态

比赛开始前，主办方将统一重置参赛 Agent 的出生位置、背包、末影箱、经验、状态效果和 advancement 进度。所有参赛者使用相同的游戏版本、共同在同一个服务器中游玩。

比赛过程中，Agent 必须通过主办方公开的赛事 API 自主完成观察、决策和操作。**除处理赛事平台故障外，不得由人工代替 Agent 进行游戏操作**，也不得使用服务器命令、管理员权限、未公开接口或直接读取世界存档等方式获取额外信息或资源。

## 4. 计分方法

初赛采用百分制，总成绩由“游戏表现分”和“工程评审分”两部分组成：

> **初赛总成绩 = 游戏表现分（60 分）+ 工程评审分（40 分）**

### 4.1 游戏表现分（60 分）

比赛仅统计主办方赛前公布的**原版非配方 advancement（进度）**。配方解锁、服务器自定义 advancement 以及比赛时间外完成的 advancement 均不计分。同一个 advancement 只能获得一次分数。

每个 advancement 的分数由“完成难度”和“进度树深度”共同决定：

> **单项分数 = 难度基础分 + 5 × 进度树深度**

难度基础分：

| 难度等级 | 说明 | 基础分 |
|---|---|---|
| 1 | 基础动作，通常可以在游戏早期自然完成 | 5 |
| 2 | 简单制作、交互或短距离探索 | 15 |
| 3 | 需要一定资源积累、结构探索或战斗准备 | 30 |
| 4 | 需要稀有资源、复杂战斗、长距离探索或精确操作 | 60 |
| 5 | 需要大规模收集、复合条件或极高执行难度 | 100 |

进度树深度从各分类的根节点开始计算：根节点深度为 0，其直接子节点深度为 1，之后逐级增加。各分类根节点本身为 0 分。

每个 advancement 的难度等级、深度和最终分值**以主办方赛前发布的计分表为准**。参赛者的游戏原始分计算方式为：

> **游戏原始分 = 8 小时内所有已完成计分 advancement 的分数之和**

所有有效参赛者的游戏原始分将以本届初赛的最高游戏原始分为基准，线性归一化为 60 分：

> **游戏表现分 = 参赛者游戏原始分 ÷ 本届最高游戏原始分 × 60**

本届游戏原始分最高的有效参赛者获得 60 分，其他参赛者按比例折算。若所有有效参赛者的游戏原始分均为 0，则所有参赛者的游戏表现分均记为 0 分。

完成状态和完成时间均以赛事服务器保存的记录为准，客户端显示、Agent 自行报告或本地日志不能替代裁判记录。

### 4.2 工程评审分（40 分）

组委会将组织不少于 3 名评委对参赛者提交的 harness 和 Agent 工程进行评审，每位评委独立给出 0–40 分。评审主要考察以下方面：

- harness 与 Agent 整体设计的完善性；
- 方案、策略或技术实现的新颖性；
- 工程结构、代码组织和实现逻辑的清晰度；
- 系统的稳定性、可复现性、可维护性及其他综合工程表现。

汇总评委分数时，去掉一个最高分和一个最低分，再对其余评委分数取算术平均值，作为该参赛者的工程评审分。若有多个相同的最高分或最低分，仍分别只去掉其中一个。工程评审分保留两位小数。

### 4.3 初赛总成绩

> **初赛总成绩 = 游戏表现分 + 工程评审分**

初赛总成绩满分为 100 分，保留两位小数，并作为初赛排名的主要依据。

## 5. 并列判定

若两名或多名参赛者的初赛总成绩相同，依次按照以下规则确定名次：

1. 游戏表现分较高者优先；
2. 若仍相同，完成难度等级 5 的 advancement 数量更多者优先；
3. 若仍相同，比较难度等级 4 的完成数量，并依次向下比较；
4. 若仍相同，以较早达到最终游戏原始分者优先；
5. 若仍无法区分，则并列排名。

## 6. API 能力说明

赛事 API 不保证能够完成游戏中的每一个原版 advancement，参赛者应根据公开接口的实际能力自行选择任务和制定策略。

## 7. 成绩与申诉

比赛结束后，主办方将公布游戏原始分、游戏表现分、工程评审分、初赛总成绩，以及已完成 advancement 和对应完成时间。参赛者如对成绩有异议，应在成绩公布后的指定期限内提交申诉；主办方将以服务器记录、赛事运行日志和评审记录作为最终裁定依据。

主办方保留对未尽事宜进行解释和补充的权利。任何补充规则均应在生效前向所有参赛者统一公布。

决赛的比赛形式、计分方式及具体规则将另行通知。
