# 策略测试与赛前调整

> 这里说的「策略」= **这局怎么打**（目标/优先级/约束）。
> **推荐写 `Codes/data/strategy.md`（自由文本，LLM 自己拆解）**；JSON 仅作兼容。
> 保存后**下一个决策就生效**，不用改代码、不用重启。

---

## 1. 策略在哪里（四个杠杆）

| 想改什么 | 改哪里 | 生效时间 | 风险 |
|---|---|---|---|
| **打法/目标/优先级/约束** | **`Codes/data/strategy.md`（推荐，自由文本）** | **下一个决策**（热更新） | 低 |
| 兼容的结构化策略 | `Codes/data/strategy.json` | 下一个决策 | 低 |
| 决策原则（提示词） | `Codes/planner.py` 的 `SYSTEM_PROMPT` | 重启程序 | 中 |
| 模型失灵时的兜底动作 | `Codes/planner.py` 的 `_fallback` | 重启 | 中 |
| 技能参数 / 新技能 | `Codes/skills.py` | 重启 | 高（要测试） |
| 计分表 | `Codes/data/advancement_scores.json` | 重启（启动时加载） | 低 |
| 吃喝/逃跑/预算/拉黑阈值 | `Codes/config.py` | 重启 | 低 |

**优先级建议**：能改策略文件就不改代码；必须改代码时，先在 `python main.py mock` 和单测里跑通，再上真服。

---

## 2. 策略文件（`strategy.md` 优先）

### 2.1 推荐：自由文本

```bat
copy data\strategy.example.md data\strategy.md
notepad data\strategy.md
```

内容不用套字段，例如：

```markdown
目标：优先下界线，能做多深做多深；末地随缘。
时间：前 1 小时基础，之后主攻下界，最后 40 分钟扫便宜分。
约束：不要打袭击；不要碰需要酿造全药水的分。
备注：岛上有村庄就先交易。
```

LLM 会自己阅读、拆解成“下一步做什么”；**不预设 phases/targets**。
`python main.py strategy` 查看的是 md（存在时）；`run` 也优先读 md。

### 2.2 兼容：`strategy.json`

```json
{
  "mode": "balanced",
  "risk": "medium",
  "branch_priority": ["nether", "village", "trial", "husbandry", "adventure", "end"],
  "phases": [
    {"name": "开局", "until_min": 60,  "focus": "bootstrap"},
    {"name": "下界", "until_min": 210, "focus": "nether"},
    {"name": "末地", "until_min": 330, "focus": "end"},
    {"name": "中盘", "until_min": 450, "focus": "best_available"},
    {"name": "扫尾", "until_min": 480, "focus": "cheap_points"}
  ],
  "targets": ["minecraft:nether/obtain_blaze_rod"],
  "avoid": ["minecraft:nether/all_potions"],
  "notes": "给自己看的备注"
}
```

> 默认 `strategy.json` 是空的；只有在显式写 phases/targets 时才会启用预设。
> 同时存在 md 和 JSON 时，**md 优先**；JSON 的 `avoid` 仍用于候选过滤。

| 字段 | 含义 |
|---|---|
| `mode` | 打法名字，只用于显示/日志（`balanced` / `nether_rush` / `safe_bootstrap`…） |
| `risk` | `low` / `medium` / `high`，写进提示词，影响模型冒险程度 |
| `branch_priority` | 分支优先级（`nether` / `village` / `trial` / `husbandry` / `adventure` / `end`） |
| `phases` | 时间规划：`until_min` 是「本地已运行到第几分钟」，`focus` 是这阶段重点 |
| `targets` | 明确要冲的 advancement id（会排到候选最前面） |
| `avoid` | 明确不碰的 id（会从候选里过滤；模型选了也会被清空） |

`focus` 可选：`bootstrap`（基础）、`nether`（下界）、`end`（末地）、`best_available`（挑分高的）、`cheap_points`（扫低难度）、`custom`。

> ⚠️ 策略是**软约束**：它写进提示词、过滤候选，但模型仍可能选别的。
> 想要「硬流程」（必须按剧本走），需要下一步的 `scheduler.py` 任务图。

## 4. 怎么测试策略（三层）

### 第一层：离线（0 成本，只验证不回归）

```bat
python main.py mock --ticks 20
python -m unittest discover -s tests -v
python main.py ping --samples 5
```

能验证：技能链路、状态恢复、防死循环、策略文件解析、网络延迟。
**验证不了**：模型的真实决策（mock 用的是固定剧本）。

> 没有模型余额 / 不想花 token 时，可以跑「本地规则模式」：
>
> ```bat
> python main.py run --minutes 10 --no-llm
> ```
>
> 只用兜底规则（砍树→采集→合成→勘察）推进，不会调用模型；
> 适合验证桥接、技能和防死循环，不适合评估模型策略。

### 防死循环机制（已经内置，不用你管）

| 情况 | 处理 |
|---|---|
| 动作被拉黑 | **当轮**就改做能推进的动作（砍树/采集/勘察），不是干等下一轮 |
| 同一个动作连续 3 次 | 强制换一个 |
| 连续 4 轮位置/背包/进度都没变 | 判定空转，强制推进 |
| `timeout` / `network_error` / `busy` 等临时错误 | **不拉黑**，只重试 |
| `scan` / `survey` 观察类 | 不拉黑（空转由上面的检测处理） |
| 模型 `HTTP 402` 余额不足 / 401 key 错 | **直接停**，不再空转（日志会写清楚原因） |

### 第二层：局域网（推荐，真实动作、不花比赛服时间）

前提：桥接已启动（`Codes/local_bot`），`BACKEND=my_server`。

```bat
python main.py reset
python main.py run --minutes 15
python main.py report
```

看四件事：**决策数/分钟、技能成功率、完成进度、死亡次数**。

### 第三层：比赛服练习窗口

真实接口 + 真实计分，最终确认。和上面一样跑 15~30 分钟，看 `report` 与 `logs/run-*.jsonl`。

## 5. A/B 对比一套策略（照着做）

```bat
:: 1) 记录 A（默认策略）
python main.py reset
python main.py run --minutes 15
python main.py report > logs\A.txt

:: 2) 记录 B（另一套策略；不用改默认文件）
python main.py reset
python main.py run --minutes 15 --strategy data\strategy_nether.json
python main.py report > logs\B.txt

:: 3) 对比
type logs\A.txt
type logs\B.txt
```

| 技能成功率（craft/chop_tree） | | |

## 6. 比赛当天怎么改策略

1. 直接改 `Codes/data/strategy.json`，**保存即生效**（下一轮决策读新文件）；
2. 改完看一眼有没有写错：

   ```bat
   python main.py strategy
   ```

   - 会打印当前策略、当前阶段（按本地运行时间）、以及**拼错的 id 提示**；
3. 改坏了不会崩：读取失败会**沿用上一份**；
4. 想换提示词/技能 → 重启程序（规则允许；`supervisor.py` 会自动拉起）；
5. 建议赛前准备 2~3 个策略文件，现场用 `--strategy` 切换；
   如果跑的是 `supervisor.py`，直接覆盖 `data/strategy.json` 更省事（下一轮生效）。

## 8. 常见误区

| 误区 | 事实 |
|---|---|
| 「改了 strategy 就会严格按它走」 | 它是软约束（提示词 + 候选过滤），模型可能不听话；硬流程要 scheduler |
| 「阶段按比赛剩余时间算」 | 按**本地运行时间**（`state.started_at`）；中途 `reset` 会从 0 重算 |
| 「改 avoid 能取消已完成的进度」 | 不能，只是不再冲 |
| 「只改 focus=nether 就行」 | 没有下界技能（portal/fortress）时执行不了，会退化成基础任务 |
| 「计分表就是策略」 | 计分表决定「值多少分」，策略决定「先做哪个」 |

## 9. 下一步（把策略变成硬流程）

现在 `strategy.json` 只影响提示词和候选。要真正「按剧本执行」，需要 `scheduler.py`：

```
phases → campaigns（每阶段一组任务）
campaign → 节点 DAG（每个节点 = advancement + 技能序列 + 校验）
失败/超时 → 回退到 LLM 重规划
```

这样 A/B 更可控，也更适合工程评审讲「规划调度」。开发量约 1~2 天，等当前基线跑顺了再做。
