# 局域网测试指南（在自己的世界跑这个 Bot）

> 目标：不连比赛服，也能验证「Agent 会不会走路、挖矿、合成、吃东西、打架」。
> 适合赛前调试技能、验证改动、给朋友演示。

---

## 0. 先搞清楚一件事

**这个项目里没有「Bot 本体」。**

- 比赛时：Bot 跑在 NMO 的服务器上，我们只是通过 HTTP 接口（`mc-api.windywindie.top`）给它下命令；
- 本地：没有那个服务，所以**必须自己起一个 Mineflayer bot**，再套一层「同款 HTTP 接口」；
- 这层桥接已经给你写好了：`Codes/local_bot/`（Node.js + Mineflayer）。

```
Minecraft 局域网世界  ←  Mineflayer（Codes/local_bot/server.js）
        ↑
  HTTP :8099
        ↑
Codes/main.py（BACKEND=my_server）
```

## 1. 三档测试，按需要选

| 档位 | 命令 | 需要 Minecraft | 能测什么 |
|---|---|---|---|
| ① 纯逻辑 | `python main.py mock` | ❌ | 主循环、技能、计分、状态恢复（假服务器） |
| ② 局域网 | 本文档 | ✅ | 真实寻路/挖/放/合成/战斗（推荐赛前） |
| ③ 比赛服 | `python main.py run` | ✅（远程） | 最终联调（用比赛账号） |

## 2. 准备工作

1. **Node.js 18+**：<https://nodejs.org/> 下载 LTS，安装后 `node -v` 能出版本号；
2. **Minecraft Java 版**：建议用 `Doc/RULES.md` 写的 **1.21.11**（和比赛一致）；
3. **Python 环境**：`Codes/venv` 已就绪（`venv\Scripts\activate`）。

---

## 3. 方案 A：单人世界「对局域网开放」（最快）

1. 启动 Minecraft，进入一个**测试用的单人世界**（别用重要存档，Bot 会真的挖和放）；
2. 游戏里按 `Esc` → **对局域网开放**；
3. 游戏模式选「生存」，允许作弊可选（建议开，方便 `/tp` 救场）→ 点「创建局域网世界」；
4. 聊天栏会显示：

   ```
   Local game hosted on port 54321
   ```

   **记下这个端口**（每次重开都会变）。
5. **不要关游戏窗口、不要退到主菜单**；也尽量别长时间停在暂停菜单——
   单人 LAN 世界的「服务器」就是你的客户端，暂停可能让 Bot 卡住。
6. 建议先用「和平」难度跑通走路/挖矿，再切「普通」测战斗。

> 小技巧：想测村庄/试炼密室，可以在创建世界时选「村庄」超平坦预设，或进去后用 `/locate structure village` 再 `/tp` 过去。

---

## 4. 方案 B：本地 Paper 服务器（更稳，推荐长时间测试）

如果 Bot 要跑几十分钟，建议用独立服务端：

1. 下载 [Paper](https://papermc.io/downloads)（版本与客户端一致，如 1.21.11），放到一个新文件夹；
2. 第一次运行 `java -jar paper.jar --nogui`，会生成配置并退出；
3. 改 `eula.txt`：`eula=true`；
4. 改 `server.properties`：

   ```ini
   online-mode=false
   enforce-secure-profile=false
   spawn-protection=0
   difficulty=normal
   gamemode=survival
   ```

5. 再启动 `java -jar paper.jar --nogui`，端口默认 **25565**；
6. 客户端「多人游戏 → 直接连接 → `localhost`」进去看一眼，确认能进。

> 如果 Bot 报 `unsupported protocol version`：给服务器装 **ViaVersion + ViaBackwards** 插件，
> 允许 Mineflayer 用它能说的协议版本连进来（见第 8 节）。

## 5. 启动本地 Bot 桥接

```bat
cd /d C:\你的路径\AIAgent4MC\Codes\local_bot
copy config.example.json config.json
notepad config.json
```

把 `mcPort` 改成你的端口（方案 A 的局域网端口，或方案 B 的 `25565`），例如：

```json
{
  "mcHost": "127.0.0.1",
  "mcPort": 54321,
  "mcUsername": "TestBot",
  "mcVersion": "",
  "apiPort": 8099,
  "apiToken": "dev"
}
```

安装依赖并启动：

```bat
npm install

:: 先自检：只测「这个端口能不能连上」，不启动 bot
node check.js

:: 自检通过再启动
npm start
```

看到这些就成功了：

```
 本地 Bot 桥接已启动（只监听 127.0.0.1）
   接口地址：http://127.0.0.1:8099/api/v1
   鉴权 token：dev
   ...
[bridge] bot 已上线：TestBot @ [12.5, 65, -3.2]
```

浏览器打开 <http://127.0.0.1:8099/health> 应该看到 `{"ok":true,"ready":true,...}`。

> 国内 npm 慢：`npm install --registry=https://registry.npmmirror.com`

### 5.0 窗口怎么摆（敲不了命令先看这里）

`npm start` 是**常驻服务**，那个窗口会一直被占用，不能再在里面敲 Python 命令。推荐这样摆：

| 窗口 | 放什么 |
|---|---|
| 窗口 A（双击 `start_bridge.bat`，或 `npm start`） | 桥接，一直开着；关掉窗口 = 停 Bot |
| 窗口 B（**另开**一个 cmd / PowerShell） | `python main.py status`、`run` 等命令 |
| 游戏窗口 | 改成**窗口化**，不要全屏 |

如果游戏窗口抢焦点/全屏，切到终端时按键进不去：

- 按 `Alt + Tab` 切窗口；`Alt + Enter` 或 `F11` 退出全屏；
- 单人世界**失去焦点会暂停**，Bot 会卡住 → 改游戏目录下 `options.txt` 里的
  `pauseOnLostFocus:false`（你的游戏目录是 `D:\你的游戏目录\.minecraft\versions\<版本>\`，
  文件路径 `...\<版本>\options.txt`；找不到就在 `.minecraft` 下搜）；
- 切到终端后回游戏看一眼：**太阳/生物还在动**，说明没暂停，Bot 才能继续；
- 如果 PCL 开了「游戏窗口置顶」，先关掉，否则终端会被压在下面。

> 最省心的是**方案 B 专用服**：游戏窗口根本不用开，Bot 连 `25565`，你在终端随便敲命令。

### 5.1 连不上（`ECONNREFUSED`）怎么办
`ECONNREFUSED` 的含义很明确：**这个端口没有任何程序在监听**。不是 Python 的问题，也不是桥接的 bug。

先跑自检：

```bat
node check.js
```

它会直接告诉你连不上，并给出检查顺序。然后按下面查：

**① 用原版客户端验证端口**

`多人游戏 → 直接连接 → 127.0.0.1:<端口>`，能进 → 端口是对的，问题在桥接配置；
进不去 → 世界/服务器那边的问题，先解决它。

**② 查谁在监听（PowerShell）**

```powershell
Get-NetTCPConnection -State Listen |
  Where-Object {$_.OwningProcess -in (Get-Process java -ErrorAction SilentlyContinue).Id} |
  Select-Object LocalAddress, LocalPort, OwningProcess
```

- 一行都没有 → Minecraft 根本没开世界/服务器没启动；
- 只有 `25565` 之类，没有 `25526` → 你 `config.json` 里的端口写错了；
- 只有 `[::]` / `::1` → 试 `mcHost: "::1"`；
- 只有 `192.168.x.x` → 服务器绑了局域网 IP（`server-ip`），把 `mcHost` 改成那个 IP。

**③ 常见三种真实原因**

| 原因 | 怎么确认 | 怎么修 |
|---|---|---|
| 单人 LAN 世界已经退到主菜单/关了 | 游戏里还能看到世界吗 | 重新「对局域网开放」，端口会变，改 `config.json` |
| 端口抄错/过期 | 聊天栏那行 `Local game hosted on port XXXXX` | 用最新那次的端口 |
| 专用服没启动 / 还在启动 | 控制台有没有 `Done (xx.xxxs)!` | 等它启动完；确认 `server.properties` 的 `server-port` |

> 专用服还要 `online-mode=false`（否则离线 bot 会被踢），端口默认 `25565`。
>
> 另外：`25526` 这种端口不太像 Minecraft 随机分配的 LAN 端口（LAN 通常是 5 万多），
> 更像手动配置的 `server-port`——请优先确认你连的到底是「单人 LAN 世界」还是「专用服」。

**④ 修好后不用重装**

桥接现在会**每 5 秒自动重连**；Minecraft 那边弄好后它会自己连上（也可以 `Ctrl+C` 重启 `npm start`）。

## 6. 让 Python 端连本地

先测一下延迟（桥接没启动会显示 `ConnectionRefused`，属正常提示）：

```bat
python main.py ping --samples 3
```

编辑 `Codes/.env`：

```ini
BACKEND=my_server
MY_SERVER_BASE=http://127.0.0.1:8099
MY_SERVER_TOKEN=dev
```

先看状态：

```bat
cd /d C:\你的路径\AIAgent4MC\Codes
venv\Scripts\activate
python main.py status
```

应该打印 Bot 的坐标、血量、背包。再跑 10 分钟：

```bat
python main.py run --minutes 10
```

跑完看 `Codes/logs/run-*.jsonl` 和项目根目录的 `任务记录.md`。

> **不想花 token / 没有模型余额**：加 `--no-llm`，只用本地规则跑（砍树/采集/合成/勘察）：
>
> ```bat
> python main.py run --minutes 10 --no-llm
> ```
>
> 适合验证桥接和技能链路；它不会“思考”策略，只会按固定优先级推进。

## 7. 验证清单（照着打勾）

| 能力 | 怎么验证 | 期望 |
|---|---|---|
| 连接 | `python main.py status` | 坐标/血量/背包正常 |
| 走路 | `run` 模式第 1 轮（或 LLM 说 move_to） | Bot 在游戏里移动 |
| 砍树 | `run` 或让 LLM 调 `chop_tree` | 原木进背包 |
| 挖矿 | `survey` → `collect group=stone` | 圆石进背包 |
| 合成 | 有木头后 `craft wooden_pickaxe` | 背包出现镐 |
| 吃东西 | 背包有食物、饥饿 <14 | 自动吃 |
| 战斗 | 附近有怪，`attack` | 怪物掉血/死亡 |
| 容器 | 放熔炉 → `smelt raw_iron` | 铁锭进背包 |
| 聊天 | `POST /chat` | 游戏里出现消息 |

手动打接口（Windows 自带 `curl.exe`）：

```bat
curl -H "Authorization: Bearer dev" http://127.0.0.1:8099/api/v1/status

curl -X POST -H "Authorization: Bearer dev" -H "Content-Type: application/json" ^
  -d "{\"types\":[\"oak_log\"],\"radius\":16}" ^
  http://127.0.0.1:8099/api/v1/find_blocks
```

## 8. 常见问题

| 现象 | 原因 / 解决 |
|---|---|
| `ECONNREFUSED 127.0.0.1:xxxxx` | 端口没人监听：先 `node check.js`，再按 §5.1 查（世界是否还开着 / 端口 / 专用服是否启动） |
| `unsupported protocol version` | Mineflayer 不支持该版本。给服务器装 ViaVersion/ViaBackwards，或把 `mcVersion` 改成 Mineflayer 支持的版本，或 `npm install mineflayer@latest` |
| `bot 被踢` | 用户名重复 / 服务器开了正版验证（`online-mode=true`）/ 白名单 |
| `ready:false` 一直不变 | Bot 没进世界：看桥接窗口日志；LAN 主机暂停了游戏 |
| 合成总是 `missing_ingredients` | 本地桥只认「背包 + 附近工作台」；先 `craft crafting_table` → `place` 再试 |
| 掉落物捡不到 | 没装 `mineflayer-collectblock`，或物品掉进岩浆/虚空 |
| `advancements not implemented` | 正常：本地桥不统计进度，Agent 会走基础任务 |
| 反复「跳过 craft / 同一个动作」 | 旧版桥接把「缺木板」误判成「需要工作台」。更新 `local_bot` 后 **重启 `npm start`**；再 `python main.py reset` 清掉拉黑记录 |
| 中文乱码 | 先 `chcp 65001` |

## 10. 限制与注意

1. **本地桥接不是比赛方服务端**：它是本项目自己写的简化 Mineflayer 包装；
   主办方对接口/公式的修复只在他们服务器上，`npm install` 更新的是本地依赖，不会更新比赛方。
   要验证对方修复，只能 `BACKEND=nmo` 连比赛服。
2. **本地没有 advancement 进度**：`/advancements` 返回 `ready:false`，
   所以 Agent 没有分数反馈，规划会退化成基础任务，看起来“降智”；
   本地只适合验证技能/桥接/防循环，不适合比较智能程度。
3. 附魔台/酿造台/村民交易只做了基础窗口操作，复杂交互可能失败。
4. 载具驾驶、鞘翅不支持（比赛接口也不支持鞘翅）。
5. 比赛接口是主办方封装的 Mineflayer，**本地行为和比赛服不完全一样**。
6. 桥接只监听 `127.0.0.1`，**不要**改成 `0.0.0.0` 暴露到公网。
7. 用一个**单独的测试世界**，Bot 会真的破坏和放置方块。
