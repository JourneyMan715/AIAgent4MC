# 学习层与决策层

> 一句话：**赛前用 `learn` 把游戏规则学进 memory；比赛用 `run` 按你写的 `strategy.md` 打球。**
> 两个模式共享同一份世界状态和 memory，但目标不同：学习层不冲分，决策层不瞎探索。

---

## 1. 为什么分两层

| | 学习层 `learn` | 决策层 `run` |
|---|---|---|
| 目标 | 学规则、验证技能、问用户 | 按策略拿 advancement 分 |
| 是否读 strategy | **不读** | 读 `data/strategy.md`（自由文本） |
| 是否冲分 | **不冲** | 冲 |
| 是否等人输入 | **会**（有疑问就问你） | 不等人，无人值守 |
| 写什么 | `state/knowledge.json/md` | 轨迹、状态、`任务记录.md` |
| 典型时间 | 赛前 pretraining | 比赛 8 小时 |

> 只有规则学明白了，决策层才知道“什么动作会产生什么结果”。所以**先学后打**，不要一上来就让模型冲分。

---

## 2. 怎么切换

每次运行前选一个子命令即可，不需要改代码：

```bat
cd Codes
venv\Scripts\activate

:: 学习层（会停下来问你问题）
python main.py learn --minutes 20

:: 决策层（比赛/演练）
python main.py run --minutes 10

:: 只学 50 轮
python main.py learn --ticks 50

:: 清空学习记忆，从零学
python main.py learn --reset-knowledge

:: 清空世界状态（新开局）
python main.py learn --reset
```

两个模式都受 `.env` 的 `BACKEND` 控制：
- `BACKEND=nmo`：连比赛方接口（学习也会真的操作比赛服角色，慎用）；
- `BACKEND=my_server`：连本地桥接（推荐用来做学习/实验）。

## 3. 学习层怎么工作

### 3.1 一轮学习

```
观察状态/背包/事件
   ↓
若 must_ask 或有新事件 → 先问用户 / 先解释情境（不先动手）
   ↓
把「状态 + events + 当前 episode + memory」发给 LLM
   ↓
LLM 只选一个动作：
  ask_user / experiment / record_rule / record_skill / scan / survey / done
   ↓
执行并写入 memory；动作/问答/结论追加到同一 episode
   ↓
下一轮读上一轮情境，继续同一个学习线索
```

### 3.2 四种核心动作

| 动作 | 作用 | 例子 |
|---|---|---|
| `ask_user` | 有疑问直接问终端前的你，回答写入 memory | “先学木头线还是先学挖矿？” |
| `experiment` | 用技能做实验，记录成功/失败、背包变化 | `craft oak_planks`、`collect stone` |
| `record_rule` | 把结论写成规则 | “橡木原木 → 4 橡木木板” |
| `record_skill` | 把验证过的技能用法写进 memory；带 `steps` 时打包成 JSON 组合技能 | “chop_tree 前先 survey” / 木镐三步流程 |

`scan` / `survey` 是 `experiment` 的快捷方式；`done` 结束学习。

### 3.3 提问交互

学习层遇到不确定的事会直接问：

```
❓ 学习层问你：你希望先学基础合成，还是先学挖矿？
   （为什么问：两条线都合理，需要你的偏好）
> 先学基础合成
  ✅ 已记入 memory
```

- 输入 `exit` / `quit` / `退出` 可结束；
- `Ctrl+C` 也会安全收尾并导出 memory；
- 回答会进入下一轮提示词，LLM 会基于回答继续，不会重复问；
- **只有 `learn` 模式会阻塞等人**，`run` 模式不会。

### 3.4 学习阶段能做什么

**所有技能开放**（含 `attack` / `flee` / 下界相关探索）：

```
survey, scan, chop_tree, collect, craft, smelt, eat, equip, place, attack, flee, explore
```

战斗、岩浆、虚空附近先通过 ask_user 确认安全；学习层本身不替你判断风险。

### 3.5 手动测试动作（`learn --manual`）

学习层还有一个**不调用模型**的手动测试模式，适合直接试技能/接口：

```bat
python main.py learn --manual
```

进入后：

```
动作> do scan {}
动作> do craft {"item":"oak_planks","count":4}
动作> call dig {"pos":[100,64,-200],"collect":true}
动作> status
动作> inv
动作> exit
```

| 命令 | 作用 |
|---|---|
| `do <skill> [json]` | 跑一个安全技能，打印结果 + 背包变化，并写入 memory |
| `call <method> [json]` | 调原始 API（status/dig/place/craft/window…；禁止 login/connect） |
| `skills` | 列出可测技能 |
| `status` / `inv` | 看状态/背包 |
| `exit` | 退出 |

特点：**不花 token、不需要模型 key**，只要求 Bot 已登录；适合比赛前逐条验证动作。
每次 `do` 都会写 `state/knowledge.json`，决策层之后能读到。

### 3.6 和 Bot 聊天（`python main.py chat`）

聊天模式让 Bot 用 LLM 和你说话，**每条回复硬限制 25 字**：

```bat
python main.py chat
python main.py chat --minutes 10
```

- 终端输入 `你> 你好` → Bot 回复并发送到游戏聊天；
- 游戏里其他玩家说话 → 读 `/events` 的 chat 事件 → 自动回复；
- 回复前 1.2 秒冷却（`/chat` 1 条/秒限制）；
- 只聊天，不执行动作；要动作测试用 `learn --manual`。

省 token 设计：system prompt 只有一句话、不带长历史、`max_tokens=48`、
回复截断到 `CHAT_MAX_CHARS=25`。

### 3.7 先问后做、事件驱动、情境记忆

**先问后做**
- 每次 `learn` 启动时 `must_ask=true`，第一轮必须是 `ask_user`；模型若直接想做动作，会被拦下改成提问；
- 你回答后 `must_ask=false`，才允许实验；
- 中途有疑问仍可随时 `ask_user`。

**事件驱动**
- `_observe` 保存最近 8 条事件（chat/hurt/death/advancement…）；
- 提示词里的 `events` 会带上文本/伤害/攻击者，模型据此决定“先问、先躲、先验证”；
- 不会出现“刚被打了还在原地砍树”的脱离情境行为（学习层至少会把它作为情境处理）。

**情境记忆（episode）**
- 每次学习运行会开一个 `episode`：记录当时的坐标/维度/血量/背包/事件；
- 每次 `ask_user` / `experiment` / `record_rule` / `record_skill` 都追加一条 `turn`；
- `memory.summary()` 会把**最近一段情境 + 最近 4 个动作**放进提示词，模型能接着上一轮做；
- 结束时写 `lesson`，并在 `knowledge.md` 的“学习情境”里导出。

这样学习不是一堆孤立实验，而是“在什么情境下 → 问了什么 → 做了什么 → 学到什么”的连续记录。

**自动停止**
- 模型返回 `done` / `finish` / `complete` / `task_complete`（或 `done: true`）时立即收尾；
- 连续 **10 轮** 动作/上下文完全相同（`LOOP_LIMIT`）判定死循环，自动停止并写轨迹；
- 所有模式都有这个 10 轮检测；`run`/`chat`/`manual` 也会在同样条件下停。

### 3.8 把学到的流程打包成 JSON skill

学习层验证出稳定流程后，用 `record_skill` 带 `steps`：

```json
{
  "action": "record_skill",
  "name": "make_wooden_pickaxe",
  "description": "砍树→木板→木棍→木镐",
  "args": {},
  "steps": [
    {"skill": "chop_tree", "args": {}},
    {"skill": "craft", "args": {"item": "wooden_pickaxe", "count": 1}}
  ]
}
```

会写入：

- `state/knowledge.json` 的 `skills`（给提示词看）；
- `state/skills.json`（可执行的 JSON macro）。

以后决策层只需输出 `{"skill":"make_wooden_pickaxe","args":{}}`，执行器按 `steps` 逐条调用已有技能，
模型不用每一步重新决定底层动作。`python main.py skills` 可查看全部 JSON skill。

`data/skills.json` 现在每个条目都可执行：

- 原子技能：`type=python` + `handler=chop_tree` + `executable=true`；
- 内置组合：`bootstrap_wood` / `bootstrap_stone`，`type=macro` + `steps`；
- 学习组合：`state/skills.json`，同样 `type=macro` + `steps`。

执行器 `skills_registry.execute(api, state, name, args)` 统一分发，不需要模型拼 Python；一次决策选一个 macro 即可。

## 4. Memory 里存什么

### 4.1 文件

| 文件 | 内容 | 谁读 |
|---|---|---|
| `Codes/state/knowledge.json` | 机器可读：rules/skills/qa/experiments | 学习层、决策层 |
| `Codes/state/knowledge.md` | 人类可读导出 | 你、评审 |
| `Codes/state/world_state.json` | 坐标/背包/进度/失败 | 两个模式 |

> `state/` 已在 `.gitignore` 里，不会把学习记忆/账号数据提交到仓库。

### 4.2 结构

```json
{
  "rules": [
    {"topic": "木材", "rule": "橡木原木可以合成 4 个橡木木板",
     "source": "llm", "evidence": "craft 实验", "at": "..."}
  ],
  "skills": [
    {"name": "chop_tree", "notes": "先 survey 再砍，避免虚空", "args": {}}
  ],
  "qa": [
    {"q": "先学什么？", "a": "先学基础合成", "at": "..."}
  ],
  "experiments": [
    {"skill": "craft", "args": {"item": "oak_planks"}, "ok": true,
     "summary": "合成 oak_planks×4", "delta": {"oak_log": -1, "oak_planks": 4}}
  ],
  "episodes": [
    {"id": "ep-20261115-...", "context": {"pos": [0,64,0], "events": ["受伤 -2"]},
     "turns": [
       {"kind": "ask", "question": "先学什么？", "answer": "木头"},
       {"kind": "experiment", "skill": "scan", "ok": true, "summary": "看到树"}
     ],
     "lesson": "先找树"}
  ]
}
```

### 4.3 决策层怎么用

`Planner` 每次决策都会把 memory 摘要放进提示词：

```
【已学规则】
- [木材] 橡木原木可以合成 4 个橡木木板
【已验证技能】
- chop_tree：先 survey 再砍
【用户确认】
- 问：先学什么？ 答：先学基础合成
```

这样学习层的成果会直接影响比赛决策，不是“学完就忘”。

## 5. 策略层：你和 LLM 完全接管

### 5.1 推荐：写 `data/strategy.md`

不再预设阶段/路线。你写自由文本，LLM 自己阅读、拆解：

```markdown
# 这局怎么打

目标：优先下界线，能做多深做多深；末地随缘。
时间：前 1 小时基础，之后主攻下界，最后 40 分钟扫便宜分。
约束：不要打袭击；不要碰需要酿造全药水的分。
备注：岛上有村庄就先交易。
```

启动：

```bat
python main.py run --minutes 10 --strategy data\strategy.md
```

或者直接把文件命名为 `Codes/data/strategy.md`，`run` 会自动优先读它。

### 5.2 不写 strategy 会怎样：自主普通游戏

- 启动时检查 `strategy.md` 和 `strategy.json`，**都为空** → 自动进入**自主普通游戏模式**；
- Planner 读 memory（规则/技能/情境）+ 当前状态，自己决定生存/探索/资源/建造；
- **赛前默认关闭比赛规则**（`COMPETITION_MODE=False`），不按 advancement 分数优化；
- 比赛当天加 `--competition`（或 `.env` 设 `COMPETITION_MODE=true`）才启用计分驱动。

### 5.3 JSON 还保留吗

保留，作为兼容/备用：

```bat
python main.py run --strategy data\strategy_safe.json
```

但推荐优先用 `strategy.md`；两者同时存在时 **md 优先**，LLM 以自由文本为准。

### 5.4 热更新

- 改 `strategy.md` / `strategy.json` 保存后，下一个决策生效，不用重启；
- 文件写坏不会崩：读取失败沿用上一份；
- `python main.py strategy` 可以查看当前策略（md 优先）。

## 6. 建议的赛前流程

```bat
:: 1) 本地桥接 + 学习层，先学基础规则
cd Codes\local_bot
npm start

:: 另一个窗口
cd Codes
venv\Scripts\activate

:: 2) 看学到什么
type state\knowledge.md

:: 3) 写 strategy.md
copy data\strategy.example.md data\strategy.md
notepad data\strategy.md

:: 4) 本地演练（不花 token 可加 --no-llm）
python main.py reset
python main.py run --minutes 15

:: 5) 换比赛方接口，短跑验证
::    先把 .env 改成 BACKEND=nmo
python main.py test-mc
python main.py run --minutes 10
```

> 学习层会真的操作角色（砍树/合成/走位），请用**单独的测试世界**。
> 比赛当天不要再跑 `learn`（它会停下来等人）。

## 7. 接口覆盖（v1.3）

比赛方接口已全部封装在 `Codes/mc_api.py`：

| 分类 | 方法 |
|---|---|
| 认证 | `login` / `logout` |
| 连接 | `connect` / `disconnect` |
| 观察 | `status` / `inventory` / `find_blocks` / `get_block` / `get_entities` / `events` / `advancements` |
| 移动/挖掘/放置 | `move_to` / `dig` / `place` |
| 交互/使用 | `interact` / `use_item` |
| 战斗 | `attack` / `shoot` |
| 合成 | `craft` |
| 窗口 | `window_view` / `window_act` |
| 装备/姿态 | `equip` / `posture` |
| 载具/丢弃/聊天/中断 | `dismount` / `drop` / `chat` / `stop` |

通用参数 `stop_on` 已加到所有会执行动作的方法（默认不传，由服务端决定 `["hurt","death"]`）。
`my_server` 适配器也同步支持。

## 8. 常见问题

### 8.1 学习层会不会很烧 token？

一次学习约 1.5~2k 输入 token；30 分钟几十轮，通常不到 10 万。比 8 小时比赛预算小得多。
`learn --ticks 20` 可以先试水。

### 8.2 学习层能自己“学会合成表”吗？

它是**实验 + 记录**：做一次 `craft`，看结果/错误，把结论写进 memory；
不会自动生成完整配方数据库。要系统学，可以按“木材 → 石料 → 工具 → 食物”顺序让它做实验。

### 8.3 为什么本地桥的配方老被拒绝？

见 [`配方与合成.md`](配方与合成.md)：本地桥以前拿“第一条配方”，遇到木板/木棍的多木种配方会选错；
现在会遍历所有配方，按背包实际材料 + 请求数量选，并把缺口写进 `missing_total`。

### 8.4 学习层能不能连比赛方？

可以，但会**真的操作比赛服角色**，而且会停下来等你输入；比赛当天不要用。
赛前如果只有比赛服可连，建议 `--ticks 10` 短量、只做 `survey/scan/craft`。
