# Harness 架构（设计文档 · 2026-11-13 重构版）

> 这份文档讲清楚：**这套「AI 玩 Minecraft」的东西到底怎么搭的、为什么这么搭。**
> 先讲设计原则，再画架构，最后逐层用大白话解释。对应代码都在 `Codes/`。

---

## 〇、Harness 是什么

Harness 原意是「马具」——套在马身上、让马能拉车的那套东西。

在这里它指：**把「大脑（模型）」和「手脚（游戏接口）」接起来，让它们一圈圈配合的整套框架**，包括：

- 怎么观察环境；
- 怎么决定下一步；
- 怎么把决定变成几十个具体动作；
- 怎么记住做过什么、失败过什么；
- 怎么在 8 小时里不出事、不超预算。

一句话：**模型负责「想」，框架负责「想得省、做得稳、记得住」。**

## 一、七条设计原则

### 原则 1：闭环

```
感知 → 决策 → 行动 → 反馈 → 再感知
```

没有反馈就是盲人按脚本走。现在的反馈有三路：

1. 动作返回值（挖到了什么、合成成功了没）；
2. 事件流（受伤、死亡、捡到东西、聊天）；
3. **advancement 进度**（这才是比赛的记分牌）。

### 原则 2：分层，各司其职

| 层 | 只干一件事 | 出问题只看这一层 |
|---|---|---|
| 入口层 | 解析命令、登录、等 ready | `main.py` |
| 编排层 | 串循环、保命、记账 | `agent.py` |
| 规划层 | 把状态变成「下一个技能」 | `planner.py` |
| 技能层 | 把技能变成几十个 API 动作 | `skills.py` |
| 手脚层 | 发 HTTP、统一错误 | `mc_api.py` |
| 记忆层 | 存状态、进度、失败、token | `world_state.py` |
| 日志层 | 记录每一步 | `trajectory.py` |

### 原则 3：大脑和手脚解耦

- 换模型：改 `.env` 三行，不动代码；
- 换服务器：`main.build_backend()` 换一个对象（`my_server/` 已备好）；
- 加技能：只改 `skills.py`，模型自动从提示词里知道新技能。

### 原则 4：记忆要「有用」

旧版的「经验句子」是装饰品。新版记的是**能直接影响决策的东西**：

- 已完成的 advancement（含分数）→ 决定下一步冲哪；
- 失败过的「技能+参数」→ 不再原样重试；
- 路点（工作台/熔炉位置）→ 不用每次重新找；
- token 用量 → 决定还能跑多久。

### 原则 5：容错优先

网络会断、动作会失败、模型会胡说、Bot 会死。
所以每一层都「能重试、能降级、能兜底」，而不是一出错整个崩掉。

### 原则 6：把 token 当成预算，不是免费资源 ★

比赛硬限额 800 万输入 / 150 万输出，按代理返回的 usage 统计。所以：

- 每次决策只发一小段结构化状态（约 1k tokens），**不重发聊天历史**；
- 用技能宏动作把「一次决策」放大成「几十个动作」；
- 观测带缓存、进度刷新的频率可调；
- 到 70% 提醒、98% 主动收手。

### 原则 7：一切为了「分数」★

比赛 60 分是 advancement：**每项分只由难度决定**（5/15/30/60/100，v2 草案已取消深度加成）。所以：

- 目标不是「完成用户的一句话」，而是「在剩余时间里最大化进度分」；
- `advancements.py` 提供分值，规划层据此挑目标；
- 每完成一个就立刻记账、打日志、写进状态。

## 二、整体架构

```
┌───────────────────────────────────────────────────────────────┐
│ 入口层  main.py                                                │
│   run / test-api / test-mc / status / mock / reset             │
│   build_backend() ──► 比赛服 McApi（或你自己的 MyServerApi）    │
└───────────────────────────┬───────────────────────────────────┘
                            │ 登录 + 等 ready + 加载状态
┌───────────────────────────▼───────────────────────────────────┐
│ 编排层  agent.py（主循环，无人值守）                            │
│                                                                │
│   ┌─────────────┐   ┌──────────────┐   ┌───────────────────┐  │
│   │ 观察         │   │ 保命          │   │ 时钟 / 预算 / 收尾 │  │
│   │ /status      │   │ 吃 / 逃 / 避死 │   │ 到点停 / 98% 停    │  │
│   │ /inventory   │   │ 亡循环        │   │ Ctrl+C 保存        │  │
│   │ /events      │   └──────────────┘   └───────────────────┘  │
│   │ /advancements│                                             │
│   └──────┬──────┘                                             │
└──────────┼────────────────────────────────────────────────────┘
           │ 结构化状态（坐标/血/背包/进度/失败/剩余）
   ┌───────▼────────┐        ┌──────────────────────────────┐
   │ 规划层          │  请求   │ 大脑：AIA 统一代理             │
   │ planner.py     │───────►│ 只回一个 JSON：skill + args   │
   │ 提示词约 1k     │◄───────│                              │
   └───────┬────────┘        └──────────────────────────────┘
           │ {"skill":"chop_tree","args":{...}}
   ┌───────▼────────────────────────────────────────────────┐
   │ 技能层  skills.py                                       │
   │  chop_tree / collect / craft / smelt / eat / equip /    │
   │  place / attack / flee / explore / scan / survey        │
   │  （内部：定位 → 走过去 → 挖 → 捡 → 校验，含重试与降级）    │
   └───────┬────────────────────────────────────────────────┘
           │ 底层 API 调用
   ┌───────▼────────────────────────────────────────────────┐
   │ 手脚层  mc_api.py（NMO v1.3） / my_server/（自有服）      │
   └───────┬────────────────────────────────────────────────┘
           │ HTTPS
   ┌───────▼────────────────────────────────────────────────┐
   │ 环境层：比赛服里的 Bot（真正在动）                        │
   └─────────────────────────────────────────────────────────┘

   旁路：
   world_state.py  ←→  state/world_state.json   （记忆/恢复）
   trajectory.py   →   logs/run-*.jsonl          （复盘）
                   →   任务记录.md                （给人看）
```

## 三、逐层讲清楚

### 入口层 `main.py`

- 解析命令、登录、等 Bot 进比赛服、加载状态，然后把控制权交给 Agent；
- `build_backend()` 决定用哪种「手脚」：默认比赛服；**注释里预留了自有服务器**。

### 编排层 `agent.py`

一圈四步：

1. **观察**：状态、背包（带缓存）、事件、进度（限频）；
2. **保命**：饿了吃、血少跑、连续死亡主动休息；
3. **决策**：问规划层；失败用兜底；
4. **执行**：调技能、记耗时、记失败、连续失败拉黑。

它还管：重连、重登、`ready` 等待、收尾、状态落盘。**没有 `input()`，不需要人。**

### 规划层 `planner.py`

- 系统提示 = 计分规则 + 技能清单 + 决策原则（约 1200 字符）；
- 用户消息 = 一小段 JSON（约 250 字符）；
- 输出严格 JSON，解析失败会重试一次，再失败走本地兜底策略。

### 技能层 `skills.py`

**这是分数和 token 的双重杠杆。**

| 模型说 | 代码实际做的 |
|---|---|
| `survey` | 扫 48 格方块摘要 → 识别村庄/要塞/堡垒/试炼密室/古城/珊瑚/雪原等 → 存进状态供决策 |
| `chop_tree` | 找最近的树 → 往下找树根 → 走到树下 → 自下而上挖 4~8 节 → 汇总掉落 |
| `collect group=stone count=8` | 循环：找 6 个最近石头 → 走过去 → 挖 → 确认增量 → 直到够 8 个或失败 |
| `craft item=stone_pickaxe` | 试合成 → 缺料就按服务器配方递归补 → 缺工作台就造+放 → 重试（最多 4 轮） |
| `smelt item=raw_iron` | 找/造熔炉 → 放燃料和原料 → 轮询产物 → 取出 |

技能里已经处理了「走不到、挖了没捡到、合成缺料、工作台没有」这些最常见的坑。

### 手脚层 `mc_api.py` / `my_server/`

- 统一 `{ok, result}` / `{ok:false, error:{code,message}}`；
- 业务错误抛 `McApiError(code, message)`；
- 方法名就是接口名，方便替换。

### 记忆层 `world_state.py`

- 当前状态、世界知识、运行账本；
- 原子写盘（先写临时文件再替换），断电不坏；
- 重启后接着跑，不用重新探图。

### 日志层 `trajectory.py`

- JSONL：方便程序处理、画曲线、剪高光；
- Markdown：方便人看（`任务记录.md`）。

## 四、走一遍数据流：做一把石镐

```
1. 观察    /status 背包有 4 个原木；/advancements 里 upgrade_tools 未完成（20 分）
2. 规划    模型：{"skill":"craft","args":{"item":"stone_pickaxe"}}
3. 执行    craft 试合成 → missing_ingredients（3 圆石 + 2 木棍）
           → 递归：木棍 ← 2 木板 ← 1 原木；圆石没有 → 失败返回
4. 规划    模型改口：{"skill":"collect","args":{"group":"stone","count":3}}
5. 执行    找石头 → 走过去 → 挖 3 个 → 背包 +3 圆石
6. 规划    模型：{"skill":"craft","args":{"item":"stone_pickaxe"}}
7. 执行    成功，+1 石镐
8. 记账    /advancements 刷新 → upgrade_tools 完成 +20 分 → 写状态 + 轨迹 + 控制台
```

一次「模型调用」背后是十几次 API 动作——这就是省 token 的关键。

## 五、和旧架构比

| 维度 | 旧版（v1） | 现在（v2） |
|---|---|---|
| 决策粒度 | 一个 API 动作 | 一个技能（几十个动作） |
| 上下文 | 全量聊天历史，只增不减 | 固定约 1k tokens 结构化状态 |
| 8 小时 | 约 140 轮烧完 800 万 | 约 1000 次决策 ≈ 100 万 tokens |
| 目标 | 用户一句话 | advancement 分数 |
| 运行 | 每个任务 `input()` 等人 | 无人值守，到点收尾 |
| 记忆 | 几句空泛「经验」 | 进度/路点/失败/账本，落盘可恢复 |
| 日志 | 控制台 print | JSONL 轨迹 + Markdown 总结 |
| 模型地址 | 写死 DeepSeek | `.env` 可配，比赛换代理只改三行 |
| 恢复 | 崩溃即重来 | 重启接着跑 + supervisor 自动拉起 |

## 六、以后怎么扩展

| 想干什么 | 改哪里 |
|---|---|
| 换更强的模型 | `.env` 三行 |
| 接自己的服务器 | `my_server/adapter.py` + `main.build_backend()`（已预留注释） |
| 加新技能（下界门/附魔/交易…） | `skills.py` 加一个函数 + 注册；模型自动知道 |
| 让 Bot 先学规则 | `learn.py` + `knowledge.py`；`python main.py learn` |
| 改策略/换打法 | 写 `data/strategy.md`（自由文本），或兼容 JSON |
| 改计分表 | `data/advancement_scores.json` |
| 多 Agent 协作 | 每个 Bot 一个 `Agent` 实例，共享 `world_state`（下一步） |
| 换游戏/换平台 | 写一个新的「手脚层」，上层不动 |

## 七、速查表

| 层 | 文件 | 大白话 | 平时要动吗 |
|---|---|---|---|
| 配置 | `config.py` / `.env` | 设置菜单 | ✅ 常改 `.env` |
| 入口 | `main.py` | 门卫 + 开关 | 偶尔 |
| 编排 | `agent.py` | 总管（循环） | 改节奏时 |
| 规划 | `planner.py` | 军师（读 memory + strategy，问模型） | 改提示词时 |
| 学习 | `learn.py` / `knowledge.py` | 预科班（学规则、问用户、写 memory） | 改学习目标时 |
| 技能 | `skills.py` | 招式表（真干活） | ✅ 加技能时 |
| 手脚 | `mc_api.py` / `my_server/` | 那根线（全端点 + stop_on） | 换服务器时 |
| 记忆 | `world_state.py` / `knowledge.py` | 笔记本（状态 + 规则） | 不用 |
| 日志 | `trajectory.py` | 行车记录仪 | 不用 |
| 自检 | `mock_api.py` / `tests/` | 试车场 | 改完代码跑一下 |

---

> 一句话总结：**学习层负责「先懂规则」，模型负责「想得对」，技能负责「做得快」，状态负责「记得住」，预算负责「跑得久」。**
