## 四、10:00 开跑

推荐守护模式：

```bat
python supervisor.py --until 18:00
```

或者直接：

```bat
python main.py run --until 18:00
```

**开跑后前 5 分钟盯着看**：

- 有没有登录成功、`ready` 变 true；
- 第一轮决策是不是在砍树/找资源；
- 有没有连续报错（`logs/run-*.jsonl` 最后几十行）。

## 五、跑的过程中（每 30–60 分钟看一次）

### 看什么

| 指标 | 正常 | 异常怎么办 |
|---|---|---|
| 控制台是否还在滚 | 每 10~60 秒一条 | 卡住 → 看日志；必要时重启（状态会续） |
| 完成进度数 | 稳定增长 | 长时间不动 → 可能卡在某个失败循环 |
| token 用量 | 约 1k / 次决策 | 涨太快 → 调大 `DECISION_MIN_INTERVAL` 或重启 |
| 网络延迟 | 状态 <500ms，LLM <3s | 控制台 `↔`/`🤖` 行就是每次交互延迟；看 `report` 的延迟行 |
| 死亡次数 | 偶尔 | 频繁 → 看是否夜晚/水边/矿洞，考虑改 `FLEE_BELOW_HEALTH` |
| 血量/饥饿 | 血 > 6，饥饿 > 6 | 长期低 → 检查背包有没有食物 |

### 看日志

```bat
:: 最后 20 条动作
powershell -Command "Get-Content Codes\logs\run-*.jsonl -Tail 20"
```

### 什么时候应该干预

| 情况 | 处理 |
|---|---|
| 程序崩了 | `supervisor.py` 会自动拉起；没拉起来就手动 `python main.py run`（**不要 reset**） |
| Bot 被踢/掉线 | 程序会自动重连；连续失败就 `Ctrl+C` 再重启 |
| 卡在同一个动作反复失败 | 重启（状态会记住失败黑名单，会换路）；也可改 `data/strategy.json` 换阶段 |
| 想换打法 | 直接改 `Codes/data/strategy.json`，保存后下一轮生效（`python main.py strategy` 可校验） |
| token 快用完 | 程序会主动收手；也可手动 `Ctrl+C` 保存 |
| 大量 `HTTP 402 余额不足` | 程序会**直接停止**（不再空转）；换 AIA 代理或充值后重跑 |
| 想先验证桥接/技能、不花 token | `python main.py run --minutes 10 --no-llm` |
| 快 18:00 | 什么都不用做，程序会提前 1 分钟收尾 |

> **铁律**：比赛中不要 `python main.py reset`——那会把 8 小时的进度记忆清空。

## 八、应急卡片（贴在手边）

| 症状 | 一句话处理 |
|---|---|
| 启动就退出 | `python main.py test-api` 看是不是 key/地址问题 |
| `ready=false` 很久 | 等 30 秒；还不行 `test-mc` 看登录 |
| 一直 `busy` | 等；频繁出现说明接口超时，重启 |
| 429 限流 | 程序会退避；别手动狂重启 |
| 预算耗尽 | 程序自己收尾；别再重启（一启动就会再撞预算） |
| 电脑断网 | 恢复后程序会自己重连；没恢复就重启 |
| 蓝屏/断电 | 重启电脑 → `python main.py run`（状态文件能续） |
| 掉进虚空/连续死亡 | 程序会主动休息 5 分钟；**不要 reset**，等它恢复 |
