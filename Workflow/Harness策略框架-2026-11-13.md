# Harness 策略框架（基于 `RULES.md` 草案 v2）

> 2026-11-13。依据：`Doc/RULES.md`、`Doc/agent-api-spec-dist.md`（v1.3）、
> `Codes/data/advancement_scores.json`（由 RULES.md 生成的计分表）。
> 目标：在 8 小时、单 Bot、800 万输入 token 的约束下，把「能拿的分」尽量拿满。

---

## 0. 结论先说（TL;DR）

1. **分数高度集中**：99 项计分、3385 分；但 45 项「无条件计分」就有 1200 分，下界相关 1085 分，冒险 1000 分。
2. **真正的胜负手是「岛上有下界要塞」**：有要塞 → 下界 775 分 + 药水/信标线 + 末地 210 分，上限 1200+；
   没要塞 → 上限掉到 700 左右，只能靠村庄/试炼密室/农牧/冒险凑。
3. **8 小时不是「做得多」，而是「顺序对」**：先 90 分钟打基础，再用 20 分钟勘察定路线，
   剩下时间按「分值/分钟」从高到低吃，最后 1 小时扫尾。
4. **推荐的 Harness 形态**：**LLM 只做战略（3 个介入点）+ 代码做任务图调度（DAG）+ 技能做执行**。
   不是现在这种「每圈问一次模型」，也不是写死脚本，而是「剧本 + 反射」混合。
5. **100 分项大多是陷阱**：`arbalistic`、`all_potions`、`all_effects`、`create_full_beacon`、`summon_wither`
   在 8 小时单 Bot 下成功率极低，只在条件齐备且时间富余时碰。

## 1. 规则 v2 对策略的硬约束

| 规则 | 对策略的影响 |
|---|---|
| 每人一座**虚空岛**（主世界 + 下界各一座，末地共用） | 不能靠「跑图找结构」；所有资源必须在岛上；`explore` 必须限距，掉虚空 = 死亡循环风险 |
| 岛是从正常世界截取的圆形区域，**地形/结构/箱子/生物完全相同** | 开局 20 分钟的 `survey` 决定整场路线；不同队之间是同一张图，比的是**执行顺序** |
| 计分**只看难度**（5/15/30/60/100） | 不必追求「深节点」，只按分值算账；低难度 5 分项只在顺路时做 |
| 99 项计分、其余不计分 | 不要浪费时间在标「—」的条目上（尤其 `arbalistic` 之外的 PvP/雷暴/群系类） |
| 末影龙赛前已死、禁止复活 | 末地只做「找城/鞘翅/浮空/折跃门」；`kill_dragon`、`dragon_egg` 等直接 0 分 |
| 只能在自己岛 + 末地活动 | 下界只能去自己的下界岛；末地城先到先得（16 队共享） |
| 8 小时，中断不补时 | 必须无人值守 + 崩溃恢复 + 到点收尾 |
| 800 万输入 / 150 万输出 token | 每次决策 ≤1.5k token；整场 1000 次决策 ≈ 100 万，**token 不是瓶颈，时间才是** |

## 3. 三条路线（按勘察结果分支）

### 路线 A：下界要塞 + 堡垒（上限最高，优先）

预期：**900~1400 分**（要塞 775 + 堡垒 220 + 故事 385 + 末地 210 + 零散）。

前置：进入下界（黑曜石 10 + 打火石）→ 找要塞（`nether_bricks` / `blaze_spawner`）→ 打烈焰人（烈焰棒）→ 找堡垒（`blackstone`）→ 远古残骸。

| 目标 | 分 | 依赖 | 预估 | 风险 |
|---|---:|---|---:|---|
| `enter_the_nether` | 30 | 黑曜石+打火石 | 10 min | 低 |
| `find_fortress` | 30 | 下界走一圈 | 15 min | 中（岩浆） |
| `obtain_blaze_rod` | 30 | 要塞 + 战斗 | 15 min | 中 |
| `brew_potion` | 15 | 烈焰棒 + 酿造台 | 10 min | 低 |
| `get_wither_skull` | 60 | 要塞 + 凋灵骷髅 | 30 min | 高 |
| `create_beacon` | 60 | 3  skull + 下界之星 + 铁块 | 40 min | 高 |
| `create_full_beacon` | +100 | 164 铁块 | 60+ min | 极高（陷阱） |
| `obtain_ancient_debris` | 60 | 堡垒/岩浆湖 | 25 min | 中 |

> 建议：要塞线做到 `blaze_rod + brew_potion + 末影之眼` 就够开末地；凋灵/信标线只在 15:00 前完成前置才碰。

### 路线 B：村庄 + 试炼密室（稳定中盘）

预期：**600~900 分**（村庄 195 + 试炼 150 + 基础 385 + 农牧/冒险 100~200）。

| 目标 | 分 | 依赖 | 预估 |
|---|---:|---|---:|
| `trade` | 15 | 村庄 + 绿宝石 | 10 min |
| `trade_at_world_height` | 60 | 到 y≥320 交易 | 20 min |
| `summon_iron_golem` | 30 | 铁块 4 + 南瓜 | 15 min |
| `hero_of_the_village` | 60 | 触发袭击并获胜 | 40 min（高风险） |
| `totem_of_undying` | 60 | 击杀唤魔者 | 40 min（高风险） |
| `revaulting` | 60 | 试炼密室 + 不祥之瓶 | 30 min |
| `crafters_crafting_crafters` | 15 | 合成器 | 10 min |
| `lighten_up` / `minecraft_trials_edition` | 15 / 15 | 试炼密室 | 15 min |

> 村庄线的「袭击」是双刃剑：打得过 → 60+60；打不过 → 连续死亡触发 5 分钟下线。建议装备铁套+盾再开。

### 路线 C：无结构保底（农牧 + 冒险 + 基础）

预期：**450~700 分**。

- 基础故事线：mine_stone / upgrade_tools / smelt_iron / obtain_armor / iron_tools / mine_diamond / shiny_gear / enchant_item（约 120 分）；
- 农牧批量：plant_seed / breed / tame / fishy_business / tactical_fishing / honey / wax / sign_glow（约 100~150 分，取决于岛上动物/蜂巢）；
- 冒险批量：kill_a_mob / shoot_arrow / sleep_in_bed / ol_betsy / bullseye / sniper_duel / throw_trident / two_birds_one_arrow / use_lodestone / crafter（约 200 分）；
- 下界浅层：enter / fortress 若顺路 / strider / respawn_anchor / crying_obsidian（约 100 分）。

> 这条线是「下限保险」：即使岛很穷，也要靠它把分数做到 500 左右。

## 4. 推荐的 Harness 架构（重点）

### 4.1 四种方案对比

| 方案 | 做法 | 问题 |
|---|---|---|
| ① 全 LLM 逐动作（v1） | 每个 API 动作问一次 | token 爆炸、慢、容易卡死 |
| ② 全脚本流水线 | 写死「砍树→石镐→铁镐→…」 | 岛不一样就卡住；意外无法处理 |
| ③ 纯 LLM 规划 | 每轮让模型选大目标 | 不稳定、不可复现、评审不好讲故事 |
| **④ 混合：LLM 战略 + 任务图 + 技能（推荐）** | 模型只在关键点介入，其余由代码执行 | 需要多写一层调度器（约 1~2 天） |

### 4.2 推荐形态

```
┌──────────────────────────────────────────────────────────────┐
│ 战略层（LLM，整场只调用 20~50 次）                             │
│  · 开局：读 survey + 计分表 → 选路线 A/B/C，给各阶段时间预算    │
│  · 阶段切换：完成一个 campaign 后决定「继续/切换/加塞」         │
│  · 异常：连续失败 3 次 / 死亡 / 卡住 → 重规划                   │
└───────────────────────────┬──────────────────────────────────┘
                            │ 选中的 campaign + 时间预算
┌───────────────────────────▼──────────────────────────────────┐
│ 调度层（代码，scheduler.py）                                   │
│  · 任务图（DAG）：每个 advancement = 一个节点                   │
│  · 节点字段：score / cost_min / deps / skills / verify / risk  │
│  · 优先级 = score ÷ cost × 成功率，满足依赖才可执行             │
│  · 失败重试 / 降级 / 拉黑；进度用 /advancements 校验            │
└───────────────────────────┬──────────────────────────────────┘
                            │ 下一个可执行节点
┌───────────────────────────▼──────────────────────────────────┐
│ 技能层（代码，skills/）                                        │
│  · 原子：approach / dig / place / craft / smelt / eat / equip  │
│  · 复合：chop_tree / collect / craft_chain / mine_tunnel       │
│  · 分支：portal / fortress_run / bastion_run / brew / enchant  │
│          trade / raid / breed / fish / trial_vault / end_run   │
└───────────────────────────┬──────────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────────┐
│ 执行层（mc_api.py / my_server）  +  四本账（world_state）        │
│  世界模型 / 进度图 / 失败库 / 预算与时钟                        │
└──────────────────────────────────────────────────────────────┘
```

### 4.3 为什么这样搭配

- **可靠性**：8 小时里最怕「模型抽风」。任务图是确定的，模型只做少量高层选择，失败可回退。
- **token**：整场 20~50 次模型调用（每次 1~2k），总计不到 10 万 token，远低于 800 万；省下的额度可以留给异常重规划。
- **速度**：调度器直接执行技能，不需要每步等网络；同样 8 小时能多做 3~5 倍的事。
- **评审**：任务图、优先级公式、分数曲线都是可以写进工程评审的材料（「规划调度」正是赛道明确考察项）。
- **可解释**：每一步为什么做，日志里能直接看到「节点 + 分数 + 依赖」。

### 4.4 LLM 的三个介入点（明确边界）

| 时机 | 输入 | 输出 | 频率 |
|---|---|---|---|
| 开局 | survey 摘要 + 计分表分支汇总 + 规则约束 | 路线（A/B/C）+ 时间预算 | 1 次 |
| 阶段结束 | 已完成/未完成 + 剩余时间 + token | 下一阶段（继续/切换/加塞） | 每 60~90 分钟 |
| 异常 | 最近失败、死亡、卡住的动作 | 恢复策略（换技能/换目标/撤退） | 触发式 |

> 其他时间：调度器按 DAG 自己跑，不调用模型。

## 5. 任务图与调度规则

### 5.1 节点定义（`plans/*.py` 里的数据结构）

```python
{
  "id": "nether.blaze_rod",
  "adv": ["minecraft:nether/obtain_blaze_rod"],   # 完成后校验
  "score": 30,
  "cost_min": 15,
  "deps": ["nether.enter"],
  "skills": ["goto_nether_fortress", "attack_blaze", "pickup"],
  "verify": {"adv": "minecraft:nether/obtain_blaze_rod"},
  "risk": "medium",
}
```

### 5.2 调度规则

1. 只调度**依赖已满足**且**未完成**的节点；
2. 优先级 `P = score / cost_min × success_rate`（成功率按历史统计动态调整）；
3. 剩余时间 < `cost_min × 1.5` 的节点不排（留给收尾）；
4. 同一节点失败 3 次 → 标记 `blocked`，问战略层；
5. 每完成一个节点，用 `/advancements` 核对，没完成就回滚状态并降权；
6. 死亡/掉线/预算告警 → 暂停调度，先保命/恢复。

### 5.3 依赖链示例（下界线）

```
黑曜石×10 + 打火石
   └─ portal（进下界）                      +30
        ├─ 找要塞（nether_bricks）           +30
        │    ├─ 烈焰人 → 烈焰棒              +30
        │    │    ├─ 酿造台 + 材料 → brew    +15
        │    │    └─ 末影珍珠 + 烈焰粉 → 末影之眼
        │    ├─ 凋灵骷髅×3 → 凋灵           +100
        │    │    └─ 信标（铁块×164）        +60 / +100
        │    └─ 恶魂 → 主世界击杀            +100
        └─ 找堡垒（blackstone）              +30
             ├─ 战利品箱                     +30
             ├─ 远古残骸×4 → 下界合金        +100
             └─ 猪灵交易/哭泣黑曜石          +15 / +15
```

## 8. 风险与止损

| 风险 | 触发 | 止损 |
|---|---|---|
| 掉虚空 | `explore` 走远、末地搭桥 | 限 24 格；`move_to` 失败不硬走；`on_ground=false` 立即停 |
| 死亡循环 | 3 次/60 秒 → 下线 5 分钟 | 血<6 逃跑；下界/袭击前吃满、穿铁套、带盾 |
| 下界岩浆 | 走路/挖矿掉岩浆 | 下界只走已探明路线；带水桶/方块 |
| 共享末地冲突 | 别的队先到末地城 | 末地只做「一次到位」路线，不纠缠 |
| 100 分陷阱 | 凋灵/信标/全药水 | 只在 15:00 前完成前置才尝试 |
| token 超支 | 决策过密 | 调度器模式把调用压到 50 次内 |
| 程序崩溃 | 网络/异常 | `supervisor.py` 拉起 + 状态恢复 |
| API 超时 | 长距离 `move_to` | 分段走；超时先查 `busy` |
